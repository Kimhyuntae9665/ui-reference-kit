[README로 돌아가기](../README.md) · [32개 전체 설명](../CATALOG.md) · [갤러리 사용 순서](GALLERY_SCREENSHOTS.md)

기존 20개와 다른 정보 구조·조작 방법을 추가한 21–32번입니다. 각 사진은 저장소에 포함돼 있어 GitHub에서도 바로 읽을 수 있습니다. 사진을 누르면 개별 PNG가 열립니다. 참고 이미지와 자체 시안은 같은 번호로 연결됩니다.

**읽는 순서:** 원본 사진 → 표현 원리 → 적합 업무 → 기존 후보와의 차이 → 직접 확인한 조작 → 자체 시안과 한계.

## 21 · 면적에서 시작하는 계층 확대

**참고작:** [D3 · Zoomable treemap](https://observablehq.com/@d3/zoomable-treemap) · [상세 후보 문서](../candidates/21.md)

[![21 원본 참고 화면 — D3 · Zoomable treemap](../images/21-reference.png)](../images/21-reference.png)

**화면에서 볼 부분:** 큰 사각형 안에 하위 집단을 면적으로 배치하고, 선택한 집단으로 화면 전체를 확대합니다. 상단 경로가 현재 계층을 알려줍니다.

**표현 원리:** 집단의 크기와 포함 관계를 동시에 읽는 계층 탐색

**어울리는 업무:** 업무 묶음·비용 구성·오류 유형의 드릴다운

**기존 후보와의 차이:** 13 Sankey는 이동량, 14 관계 지도는 연결을 보여줍니다. 21은 부모·자식 포함 관계와 집단 크기를 확대하며 탐색합니다.

**직접 확인한 조작과 한계:** vis를 클릭해 operator·data·controls 등 하위 집단으로 바뀌는 것을 확인했습니다.

## 22 · 조건을 동시에 좁히는 다축 비교

**참고작:** [Vega · Interactive Parallel Coordinates](https://vega.github.io/vega/examples/parallel-coordinates-interactive/) · [상세 후보 문서](../candidates/22.md)

[![22 원본 참고 화면 — Vega · Interactive Parallel Coordinates](../images/22-reference.png)](../images/22-reference.png)

**화면에서 볼 부분:** 차량 한 대가 여러 세로 축을 잇는 선으로 나타납니다. 한 축에서 범위를 선택하면 조건에 맞는 선이 강조되고 다른 선은 흐려집니다.

**표현 원리:** 여러 속성을 한 화면에서 범위 선택으로 비교

**어울리는 업무:** 대안 탐색·운영 조건 비교·다변량 이상치

**기존 후보와의 차이:** 10의 신호 트랙은 시간 변화입니다. 22의 축은 비용·품질·지연 같은 서로 다른 속성이며 한 선은 하나의 대안입니다.

**직접 확인한 조작과 한계:** Cylinders 축에서 범위를 드래그해 강조 대상이 바뀌는 것을 확인했습니다. 축 재배열·더블클릭 초기화는 공식 안내에서 확인했습니다.

## 23 · 가정을 검사하는 인과 모델

[![23 원본 참고 화면 — DAGitty v3.1](../images/23-reference.png)](../images/23-reference.png)

**화면에서 볼 부분:** 변수 역할·경로 색·분석 모드와 효과 식별 결과를 그래프 주변에 배치합니다. 오른쪽 모델 코드가 그림과 함께 보입니다.

**표현 원리:** 연결의 의미와 분석 가정을 드러내는 모델 작업 공간

**직접 확인한 조작과 한계:** normal에서 moral graph로 전환해 선택 모드와 그래프 표현이 달라지는 것을 확인했습니다. 효과 식별 전체 정확성을 별도 검증한 것은 아닙니다.

## 24 · 입력·코드·결과가 이어지는 계산 노트

**참고작:** [Observable Notebooks 2.0 · System guide](https://observablehq.github.io/notebook-kit/system-guide) · [상세 후보 문서](../candidates/24.md)

[![24 원본 참고 화면 — Observable Notebooks 2.0 · System guide](../images/24-reference.png)](../images/24-reference.png)

**화면에서 볼 부분:** 설명 다음에 입력 슬라이더, 해당 입력의 코드, 계산 결과 셀이 이어집니다. 입력을 바꾸면 참조하는 결과 셀이 다시 계산됩니다.

**표현 원리:** 계산 과정과 결과를 함께 공개하는 반응형 셀

**어울리는 업무:** 업무 규칙 검토·재현 가능한 실험·분석 설명

**기존 후보와의 차이:** 20은 서사와 조작 설명을 결합합니다. 24는 셀 간 변수 의존과 재계산을 드러내므로 계산의 재현·검토에 더 적합합니다.

**직접 확인한 조작과 한계:** x 입력을 50에서70으로 바꾸자 x² 결과가2500에서4900으로 바뀌었습니다. 가이드 아래 일부 별도 라이브러리 예제 오류도 있어 전체 노트북 정상 동작을 주장하지 않습니다.

## 25 · 결과를 만져 원본을 바꾸는 편집기

**참고작:** [Sketch-n-Sketch · UIST 2019 archive](https://ravichugh.github.io/sketch-n-sketch/releases/uist-2019-acm-archive/) · [상세 후보 문서](../candidates/25.md)

**표현 원리:** 결과 직접 조작과 원본 표현의 양방향 연결

**직접 확인한 조작과 한계:** Box Volume 예시를 로드하고 핸들을 끌자 point 좌표가[102,109]에서[129,130]으로 바뀌었습니다. 합성 후보 추천의 완료·정확도는 검증하지 않았습니다.

**표현 원리:** 페이지 위치보다 수행할 동작을 먼저 찾는 탐색

**어울리는 업무:** 숙련 사용자 도구·다수 명령·빠른 대상 접근

**직접 확인한 조작과 한계:** Documentation 하위 명령을 열고 React를 입력해 검색 결과 순서가 바뀌는 것을 확인했습니다. 실제 명령의 외부 실행은 하지 않았습니다.

## 27 · 스크롤이 장면을 진행하는 공간 서사

[![27 원본 참고 화면 — SBS · The Boat](../images/27-reference.png)](../images/27-reference.png)

**화면에서 볼 부분:** 시작 뒤 스크롤 위치에 따라 배·인물·문장과 비 장면이 진행됩니다. 장 번호·소리·자동 스크롤 조작은 화면 가장자리에 있습니다.

**표현 원리:** 읽기 진행과 장면 상태를 같은 흐름으로 묶는 스크롤 서사

**어울리는 업무:** 포트폴리오 설명·문제 발생 재현·짧은 온보딩

**기존 후보와의 차이:** 20의 글 속 독립 조작과 달리 스크롤 진행 자체가 무대의 장면 상태를 바꿉니다. 지속 운영 화면보다 설명·발표에 적합합니다.

**직접 확인한 조작과 한계:** Click to start 후 스크롤해 Chapter1과 본문 장면으로 이동하는 것을 확인했습니다. 제작사의 WebGL 설명은 문서 근거이며 내부 구현을 검사하지 않았습니다.
